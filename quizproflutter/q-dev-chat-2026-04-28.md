
### Read/Write Operations

| Operation | Collection | Type | Where |
|---|---|---|---|
| `get()` | `question_bank/{category}/questions` | One-time read | `QuizProvider.loadQuiz()` |
| `add()` | `leaderboard` | Write | `QuizProvider.syncScoreToFirebase()` |
| `get()` + `orderBy` + `limit` | `leaderboard` | One-time read | `LeaderboardViewModel.fetchRankings()` |
| `add()` | `user_activity` | Write | `UserViewModel.loginUser()` |

### Real-time Listeners
❌ None. Every operation uses one-time `get()` — no `snapshots()` streams anywhere. The leaderboard does NOT auto-refresh when new scores are added.

### Query Logic
```dart
// leaderboard — ordered by score, top 20 only
.collection('leaderboard')
.orderBy('score', descending: true)
.limit(20)
.get()
```
This query requires a Firestore composite index on `score` (descending). If the index doesn't exist, it will throw a runtime error with a link to create it.

## 4. 🔐 Authentication & Security

### Authentication Method
❌ There is **no Firebase Authentication** in this project. The login screen collects name, email, and password but:
- Password is never validated or stored
- No `firebase_auth` package is used
- Login calls `ApiService.login()` → `http://localhost:3000/login` (a local Node.js server that may not even be running)
- Then calls `UserViewModel.loginUser(name)` which just saves the name in memory and logs to `user_activity`

The "logged in user" is actually stored in [globals.dart](f:\desktop_3-9-26\AVALON_smart\quizproflutter\lib\globals.dart) as a hardcoded string:
```dart
String currentUserName = "Tarun Sharma"; // ← hardcoded!
```

### Auth State Management
There is no auth state. No session persistence. If the app restarts, the user is not remembered.

### Firestore Security Rules
Not found in the project. This means Firestore is likely running in **test mode** (open read/write to everyone). This is a critical security risk in production.

### Security Risks Summary
| Risk | Severity |
|---|---|
| API keys hardcoded in `firebase_options.dart` | 🔴 High |
| No Firebase Auth — anyone can write to Firestore | 🔴 High |
| Firestore likely in open test mode | 🔴 High |
| `localhost:3000` API — will fail on real devices | 🟠 Medium |
| Hardcoded username in `globals.dart` | 🟠 Medium |

## 6. 🚨 Issues & Improvements

### Bugs
1. `topics_screen.dart` defines a class also named `HomeScreen` — if accidentally imported alongside `home_screen.dart`, it causes a compile error. The file itself has a warning comment but it's a ticking time bomb.
2. `globals.dart` has `currentUserName = "Tarun Sharma"` hardcoded — the home screen shows this name regardless of who logged in.
3. The `localhost:3000` API call in `UserRepository` and `ApiService` will always fail on Android/iOS devices (not just emulators).
4. `leaderboard` collection uses `add()` — every quiz completion creates a new document. One user can appear 50 times on the leaderboard.

### Anti-Patterns
- ViewModels bypass the entire clean architecture layer
- `FirebaseFirestore.instance` called directly in 3 ViewModels + 2 model files = 5 places (no single source of truth)
- `QuizViewModel` in `models/db_connect.dart` is misplaced — a ViewModel inside the `models/` folder
- Password field collected but never used for anything

### Performance Issues
- No caching — every screen visit re-fetches from Firestore (costs reads)
- No real-time listener on leaderboard — user must navigate away and back to see new scores
- `_questions.shuffle()` runs on the main thread inside the provider

## 8. 🎯 Best Practices & Recommendations

### Immediate Fixes (for BCA project submission)
1. Add Firebase Auth — replace the fake login:
```dart
// Replace ApiService.login() with:
await FirebaseAuth.instance.signInWithEmailAndPassword(email: email, password: password);
```

2. Fix the leaderboard duplicate problem — use `set()` with user ID as document ID instead of `add()`:
```dart
// Instead of .add({...})
await _db.collection('leaderboard').doc(userId).set({...}, SetOptions(merge: true));
```

3. Fix `globals.dart` — set `currentUserName` from the actual login input, not hardcoded.

4. Add Firestore Security Rules:
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /question_bank/{cat}/questions/{q} {
      allow read: if true;  // public read
      allow write: if false; // no one writes from app
    }
    match /leaderboard/{doc} {
      allow read: if true;
      allow write: if request.auth != null; // only logged-in users
    }
    match /user_activity/{doc} {
      allow write: if request.auth != null;
    }
  }
}
```

### For Production
- Wire the ViewModels to use the Repository/UseCase layers that already exist — the architecture is there, just not connected
- Add `keepAlive` or local caching with `SharedPreferences` for quiz questions
- Replace one-time `get()` on leaderboard with `snapshots()` stream for real-time updates
- Move `FirebaseFirestore.instance` into a singleton service — don't scatter it across files
- Delete `lib/firebase/firebase_options.dart` (stale file) and `lib/models/db_connect.dart` (dead ViewModel)
- Never commit `google-services.json` or `firebase_options.dart` with real API keys to a public GitHub repo
